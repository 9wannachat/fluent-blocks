# Decisions

- React, strict TypeScript and Vite on npm. Node is pinned in .nvmrc. The lockfile pins compatible dependencies.
- The app has light, dark and system themes. Dark is the default. The saved theme lives in the settings record and is mirrored to localStorage so index.html paints it before React loads. React applies it only after IndexedDB answers, which prevents a flash to the default. Both palettes use a clear, saturated blue (#2563eb actions) and must pass axe contrast checks. The dark palette uses a near-black background and charcoal surfaces. All routes share local shadcn/ui components for controls, cards, tabs, disclosure, navigation actions and feedback. Forms use the shadcn Native Select where browser-native selection fits. Theme values round-trip in backups.
- The curriculum uses structured TypeScript data modules with Zod runtime validation. Content and IDs can be edited separately from React. Stable IDs tie learner data to the curriculum across builds.
- Sentence construction uses a finite grammar and authored verb bank. Alternatives and open-response rubrics are authored. An unrecognized answer in a free production exercise can be self-assessed without lowering deterministic accuracy.
- Exercise attempts aggregate by objective. Completion represents the learner marking a lesson read. It is tracked independently of practice and self-assessment.
- Study storage is versioned IndexedDB. Backup merge retains the newest timestamp per ID, retaining existing records on ties. Replace validates the payload and makes a recovery copy in the same transaction.
- Spaced review uses calendar dates and 1/3/7/14/30 day intervals. Initial enqueue is available immediately. Again resets, Hard stays, Good advances one step, Easy advances two steps.
- Workbox built through vite-plugin-pwa precaches bundled assets. The app uses the browser lifecycle to detect waiting service workers and reload after activation when the learner accepts. Cloudflare Pages is the deployment target.
- V1 audio uses device speech synthesis when available. Podcast work is manual and local, and uses short original examples for the guide.
- A wrong graded answer is recorded as an attempt and stays editable for an in-place retry. Each retry check is recorded too. Reveal or a correct answer locks the exercise until ลองใหม่. Authored targeted feedback is shown on the first miss. Generic feedback never contains the model answer.
- Overview is a primary destination on every breakpoint. Lesson section labels have compact forms in lesson-sections.ts. The compact form is chosen with a container query on the tabs, so the sidebar width is taken into account. The full label is kept as visually hidden text for assistive technology and tests.
- Sentence Builder uses a radio-group of chips for option sets of up to about a dozen short items. Arrow keys move between chips. The long intention list stays a native select. Dashboard cards show an explanatory empty state rather than zero metrics.
- Type is kept light for Thai text. Headings use weights of 600–620, body text 1.7 line height, and no negative tracking. Pages and panels use generous spacing, and lesson lists are full-row links rather than underlined text.
- Buttons, chips, the theme switcher and navigation items use pill radii. Cards and inputs keep their softer rectangular corners.
- Exercise history shows only the latest outcome per exercise ID from the attempts store. Answer text is not persisted, so the backup schema is unchanged. Navigation lists use the shared RowLink and subpages use BackLink.
- Everyday English Lab has its own versioned curriculum schema. Vocabulary uses one headword with category relationships and sense-specific content. Phrasal verbs and other multi-word verbs classify object placement per sense. Contextual pattern views can reference the existing curriculum by ID.
- Everyday content IDs use the `everyday-` namespace in the existing progress, attempts and review stores. This keeps backups at version 1. Marking a word learned does not claim mastery or schedule it automatically. Adding it for review is a separate action, and Everyday Review selects only Lab items from the common queue.
- Active production matches authored answer variants and offers targeted reasons for recognized errors. Other submissions use authored self-check criteria without recording a wrong answer. The Lab uses text situations, device speech when available, and bundled data for offline access.
- Everyday search identifies the best matching sense, displays its meaning and deep-links with a `sense` parameter. Authored sense links may point to a comparison, collocation, pattern, activity, or another specific sense. Sentence workshops use the existing expansion engine and Exercise renderer. Pour and wear have deterministic Builder presets. Take off uses authored particle-placement steps.
- Sense review uses `entryId:senseId` keys with the existing review store and backup format. Bare entry IDs from earlier backups continue to resolve to the first sense, and completion remains entry scoped.
- Practical English is a versioned course pack under Learn. It composes the existing lesson, exercise and scenario schemas. Practical scenario objectives point to pack lessons, while the original scenarios still validate against Part 9. Two authored branches per flagship scenario share the existing dialogue UI and may supply graded response variants.
- Practical lesson completion and review use stable IDs in Dexie and backup version 1. End-of-module retrieval selects one authored exercise per lesson. Cross-links resolve through the original curriculum and Everyday catalog. Pronunciation examples use the optional device voice.
